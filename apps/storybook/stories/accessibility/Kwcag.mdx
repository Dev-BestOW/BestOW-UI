# KWCAG 2.2 대응 근거

**한국형 웹 콘텐츠 접근성 지침 2.2**(국가표준 KS X OT0003:2022, 4원칙 · 14지침 · 33검사항목)의 항목별로
BestOW UI 컴포넌트가 무엇을 해 두었고, 사용하는 쪽이 무엇을 해야 하는지 정리했어요.

> 이 문서는 **인증을 보장하지 않아요.** 웹 접근성 인증은 완성된 서비스 화면을 기준으로 심사해요.
> 컴포넌트가 해 둔 부분은 근거로 쓰고, "사용하는 쪽이 할 일" 과 수동 확인이 필요한 항목은 따로 점검해 주세요.

<Unstyled>
  <KwcagSummary />
</Unstyled>

- **지원** — 컴포넌트가 기준을 지키도록 만들어져 있고, 대부분 자동 검사나 테스트로 확인해요.
- **일부** — 컴포넌트는 기반을 제공하지만 사용하는 쪽의 작업이 함께 필요해요.
- **사용자 몫** — 페이지·콘텐츠 수준의 항목이라 앱에서 지켜야 해요.
- **해당 없음** — 컴포넌트에 해당 기능이 없어요(사용하는 쪽에 기능이 있으면 그쪽에서 지켜요).

번호는 표준 원문의 절 번호(5.1.1 ~ 8.2.1)예요. 원칙 번호(1.1.1 ~ 4.2.1)로 쓰는 자료도 있어요 — 5→1, 6→2, 7→3, 8→4.
인증 심사 문서에 인용할 때는 표준 원문으로 다시 확인해 주세요.

컴포넌트 하나하나의 키보드 조작과 스크린리더 동작은 [컴포넌트별 키보드·스크린리더](?path=/docs/accessibility-컴포넌트별-키보드·스크린리더--docs) 문서에 있어요.

## 어떻게 확인하나요

- **자동 검사 (CI)** — 모든 스토리를 실제 브라우저(Chromium)에서 **라이트·다크 두 테마**로 그리고 [axe](https://github.com/dequelabs/axe-core)로 검사해요.
  목록·대화상자·달력처럼 열어야 보이는 상태도 스토리의 `play` 로 열어 둔 채 검사해요. 위반이 하나라도 있으면 CI 가 실패해요.
- **단위 테스트** — 역할·이름(스크린리더가 듣는 것)으로 요소를 찾고 키보드로 조작해요. 핵심 테스트는 구현을 일부러 망가뜨려 실제로 실패하는지 확인했어요.
- **색 대비 계산** — 의미 색은 계산해서 정하고, 브랜드 색을 넣었을 때도 대비를 지키는지 테스트해요. [테마 빌더](?path=/story/foundations-theme-builder--builder)에서 직접 확인할 수 있어요.
- **수동 확인** — 읽기 순서, 실제 스크린리더 동작처럼 자동 검사로 알 수 없는 부분은 실제 브라우저에서 점검했어요.
