# 화면 패턴

여러 컴포넌트를 함께 쓰는 흔한 화면의 짜임새예요. 각 패턴은 예제 앱과 스토리에서 실제로 동작하고, E2E 테스트로 확인해요.

- 예제 앱: [주문 관리](https://dev-bestow.github.io/BestOW-UI/playground/orders)(목록·상세·등록 폼, 검색·적용한 조건 태그),
  [회원가입](https://dev-bestow.github.io/BestOW-UI/playground/signup)(react-hook-form)
- 무엇을 고를지는 [언제 무엇을 쓰나](?path=/docs/guides-언제-무엇을-쓰나--docs)를 보세요.

## 폼 검증과 오류 요약

1. 칸마다 `error` 와 `helperText`(고칠 내용)를 준다 — 칸이 `aria-invalid` 가 되고 문구가 설명으로 읽혀요.
2. 제출에 실패하면 폼 맨 위의 [ErrorSummary](?path=/docs/components-errorsummary--docs)로 **포커스를 옮긴다**.
   스크린리더가 "고칠 곳이 N개" 와 목록을 읽고, 링크로 각 칸에 바로 가요(묶음 컴포넌트는 선택된·첫 항목).
3. 다시 제출해도 오류가 남아 있으면 다시 포커스하도록 `focusKey` 에 제출 횟수를 넘긴다.
4. 브라우저 기본 검사 말풍선 대신 이 방식을 쓰려면 `<form noValidate>`.

```tsx
const [errors, setErrors] = useState<ErrorSummaryItem[]>([]);
const [submitCount, setSubmitCount] = useState(0);

<form
  noValidate
  onSubmit={(e) => {
    e.preventDefault();
    setErrors(validate());
    setSubmitCount((c) => c + 1);
  }}
>
  <ErrorSummary errors={errors} focusKey={submitCount} />
  <TextField id="name" label="이름" required error={!!message('name')} helperText={message('name')} />
  <Button type="submit">저장</Button>
</form>;
```

**react-hook-form** — 입력창은 `register` 를 펼치고, 값을 고르는 컴포넌트는 `Controller` 로 `value`·`onValueChange` 를 연결해요.
RadioGroup·AgreementGroup 같은 묶음은 ref 로 포커스할 수 없으므로 `shouldFocusError: false` 로 두고 ErrorSummary 가 포커스를 받아요.

```tsx
const { register, control, handleSubmit, formState: { errors, submitCount } } = useForm({ shouldFocusError: false });
const summary = Object.entries(errors).map(([name, e]) => ({ id: `signup-${name}`, message: e?.message ?? '' }));

<ErrorSummary errors={summary} focusKey={submitCount} />
<TextField id="signup-email" label="이메일" {...register('email', { required: '이메일을 입력해 주세요.' })}
  error={!!errors.email} helperText={errors.email?.message} />
<Controller name="plan" control={control} rules={{ required: '플랜을 골라 주세요.' }}
  render={({ field, fieldState }) => (
    <Select id="signup-plan" label="플랜" options={plans} value={field.value} onValueChange={field.onChange}
      error={!!fieldState.error} helperText={fieldState.error?.message} />
  )} />
```

**스키마로 검증하기(zod)** — 규칙을 스키마 한곳에 모으고 `zodResolver` 로 연결해요. 위와 같이 `shouldFocusError: false` + ErrorSummary.
이 코드는 패키지의 통합 테스트(`src/test/zod-form.test.tsx`)와 같아서 실제로 동작하는지 매번 확인해요.

- 한국 서비스 키트의 검증 함수를 그대로 써요 — `isValidBusinessNumber`·`isValidCardNumber`·`isValidCorporateNumber`·`hasAllRequiredAgreements` 등.
  이때 컴포넌트의 자동 검증은 `validate={false}` 로 꺼서 같은 오류가 두 번 나오지 않게 해요.
- 서식이 붙는 입력(전화·사업자번호)은 `Controller` 로 연결하면 **숫자만 있는 값**이 스키마로 가요(`010-1234-5678` 이 아니라 `01012345678`).
- 여러 칸에 걸친 규칙(비밀번호 확인)은 `.refine(…, { path: ['passwordConfirm'] })` 으로 칸을 정해요. zod 는 칸 오류가 모두 없어진 뒤에 이 규칙을 확인해요.
- **서버 오류**(이미 가입한 이메일 등)는 제출 뒤 `setError(칸, { type: 'server', message })` 로 붙여요. 클라이언트 검증을 통과해 비어 있던 오류 요약이 다시 나타나며 포커스를 받아요.

```tsx
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';
import { hasAllRequiredAgreements, isValidBusinessNumber } from '@bestow-ui/react';

const schema = z
  .object({
    email: z.string().min(1, '이메일을 입력해 주세요.').pipe(z.email('이메일 형식이 아니에요.')),
    password: z.string().min(8, '비밀번호는 8자 이상이에요.'),
    passwordConfirm: z.string(),
    phone: z.string().min(10, '휴대폰 번호를 끝까지 입력해 주세요.'),
    businessNumber: z.string().refine(isValidBusinessNumber, '올바른 사업자등록번호가 아니에요.'),
    agreements: z
      .array(z.string())
      .refine((v) => hasAllRequiredAgreements(AGREEMENTS, v), '필수 약관에 동의해 주세요.'),
  })
  .refine((v) => v.password === v.passwordConfirm, { path: ['passwordConfirm'], message: '비밀번호가 같지 않아요.' });

const {
  register,
  control,
  handleSubmit,
  setError,
  formState: { errors, submitCount },
} = useForm<z.infer<typeof schema>>({ resolver: zodResolver(schema), shouldFocusError: false, defaultValues });
const summary = Object.entries(errors).map(([name, e]) => ({ id: `join-${name}`, message: e?.message ?? '' }));

<form
  noValidate
  onSubmit={handleSubmit(async (values) => {
    const result = await api.join(values);
    if (result.emailTaken) setError('email', { type: 'server', message: '이미 가입한 이메일이에요.' });
  })}
>
  <ErrorSummary errors={summary} focusKey={submitCount} />
  <TextField
    id="join-email"
    label="이메일"
    {...register('email')}
    error={!!errors.email}
    helperText={errors.email?.message}
  />
  <PasswordInput
    id="join-password"
    label="비밀번호"
    autoComplete="new-password"
    {...register('password')}
    error={!!errors.password}
    helperText={errors.password?.message ?? '8자 이상'}
  />
  <Controller
    name="businessNumber"
    control={control}
    render={({ field, fieldState }) => (
      <BusinessNumberInput
        id="join-businessNumber"
        ref={field.ref}
        name={field.name}
        value={field.value}
        onValueChange={(digits) => field.onChange(digits)}
        onBlur={field.onBlur}
        validate={false}
        error={!!fieldState.error}
        helperText={fieldState.error?.message}
      />
    )}
  />
  …
</form>;
```

**직접 만든 입력·다른 라이브러리 입력** — [FormField](?path=/docs/components-formfield--docs)로 감싸면 TextField 와 같은 레이블·도움말·오류 연결이 붙어요.
자식 함수의 첫째 인자(`id`·`aria-describedby`·`aria-invalid`·`aria-required`)를 입력에 펼치고, `register` 도 함께 펼치면 돼요.
여러 개를 고르는 칸은 [CheckboxGroup](?path=/docs/components-checkboxgroup--docs) 을 `Controller` 로 연결해요.

```tsx
<FormField id="profile-company" label="회사명" required error={!!errors.company} helperText={errors.company?.message}>
  {(field) => <input {...field} {...register('company', { required: '회사명을 입력해 주세요.' })} />}
</FormField>
<Controller name="interests" control={control} rules={{ validate: (v) => v.length > 0 || '하나 이상 골라 주세요.' }}
  render={({ field, fieldState }) => (
    <CheckboxGroup id="profile-interests" label="관심 분야" required options={interests} value={field.value}
      onValueChange={field.onChange} error={!!fieldState.error} helperText={fieldState.error?.message} />
  )} />
```

**대화상자 안의 폼** — Modal 의 `footer` 는 form 밖에 그려지므로 제출 버튼에 `type="submit" form="폼 id"` 를 줘요.
([Modal — 폼 제출](?path=/story/components-modal--submit-form))

## 반응형 페이지 틀

좁은 화면을 먼저 만들고 넓어지면 바꿔요(모바일 우선). 구간은 `sm` 640 · `md` 768 · `lg` 1024 · `xl` 1280px 이상이고,
em 단위라 브라우저 기본 글꼴 크기를 키우면 구간도 따라 바뀌어요([Design Tokens](?path=/story/foundations-design-tokens--duration-and-z-index)).

- 페이지 본문은 [Container](?path=/docs/layout-container--docs) — 최대 폭과 좌우 여백.
- 카드 목록은 [Grid](?path=/docs/layout-grid--docs) — `columns={{ base: 1, md: 2, lg: 3 }}` 또는 칸 최소 폭만 `minItemWidth="14rem"`.
- 버튼 줄·필터 줄은 [Stack](?path=/docs/layout-stack--docs) — `direction={{ base: 'column', md: 'row' }}`. 한 줄에 다 안 들어갈 수 있으면 `wrap`.
- 구간별 값에서 주지 않은 구간은 앞(좁은) 구간 값을 이어받아요. 서버 컴포넌트에서도 그대로 써요(CSS 변수 + 미디어쿼리, JS 없음).
- 직접 스타일을 쓸 때는 `media` 를 vanilla-extract 의 `@media` 에 넣어요. 320px 에서 가로 스크롤이 없는지 확인해요(KWCAG 1.4.10 리플로).

```tsx
import { Container, Grid, media, Stack } from '@bestow-ui/react';

<Container as="main" size="lg">
  <Stack direction={{ base: 'column', md: 'row' }} justify={{ md: 'between' }} gap={3}>
    <Typography variant="h1">상품</Typography>
    <Button>상품 등록</Button>
  </Stack>
  <Grid columns={{ base: 1, md: 2, lg: 3 }} gap={{ base: 3, md: 4 }}>
    {products.map((product) => (
      <Card key={product.id}>…</Card>
    ))}
  </Grid>
</Container>;

// 직접 스타일(vanilla-extract)
export const aside = style({ display: 'none', '@media': { [media.lg]: { display: 'block' } } });
```

## 앱 뼈대 (머리글 · 사이드바 · 모바일 하단 탭바)

넓으면 왼쪽 사이드바, 좁으면 머리글의 메뉴 버튼([Drawer](?path=/docs/components-drawer--docs))과 아래 탭바로 바꿔요.
([앱 뼈대 예시](?path=/story/guides-앱-뼈대--wide) — 넓은 화면 · 휴대폰 폭 · 메뉴 열기)

- 맨 앞에 [SkipLink](?path=/docs/components-skiplink--docs), 본문은 `<main id="main" tabIndex={-1}>` — 첫 Tab 으로 메뉴를 건너뛰어요(KWCAG 6.4.1).
- 머리글은 `<header>`, 메뉴는 이름 있는 `<nav aria-label="주요 메뉴">`. 지금 페이지 링크에 `aria-current="page"` 를 주고, 색만이 아니라 굵기·배경으로도 구분해요.
- 사이드바와 탭바는 같은 메뉴라 **한 번에 하나만** 보이게 `display: none` 으로 숨겨요 — 접근성 트리에서도 빠져서 "주요 메뉴" 가 둘로 들리지 않아요(`aria-hidden` 이 아니라 `display`).
- 탭바는 4~5개, 아이콘 + 글자(아이콘만 두지 않기), 누를 자리 높이 44px 이상. 화면 아래에 붙이면 `padding-bottom: env(safe-area-inset-bottom)` 로 홈 표시줄을 비키고, 본문 아래에 탭바 높이만큼 여백을 둬요.
- 메뉴 Drawer 안의 링크를 누르면 Drawer 를 닫아요(`open`·`onOpenChange` 제어). 닫히면 포커스가 메뉴 버튼으로 돌아가요(자동).
- 라우터 링크는 `<Link as={NextLink}>`(서버 컴포넌트에서는 `asChild`). 지금 페이지는 `usePathname()` 으로 비교해요.

```tsx
// app/(app)/layout.tsx — 메뉴 상태가 있어 클라이언트 컴포넌트로 뺀 뼈대
<SkipLink />
<header className={styles.header}>
  <span className={styles.menuButton}>
    <Drawer side="left" size="sm" title="전체 메뉴" open={open} onOpenChange={setOpen}
      trigger={<IconButton aria-label="메뉴 열기" variant="ghost" color="neutral"><MenuIcon /></IconButton>}>
      <nav aria-label="전체 메뉴"><NavLinks onNavigate={() => setOpen(false)} /></nav>
    </Drawer>
  </span>
  …
</header>
<div className={styles.body}>
  <nav aria-label="주요 메뉴" className={styles.sidebar}><NavLinks /></nav>
  <main id="main" tabIndex={-1} className={styles.main}>{children}</main>
</div>
<nav aria-label="주요 메뉴" className={styles.tabbar}><NavLinks variant="tab" /></nav>

// NavLinks 의 링크 하나
<Link as={NextLink} href={item.href} aria-current={pathname === item.href ? 'page' : undefined}>
  {item.icon}{item.label}
</Link>

// layout.css.ts (vanilla-extract) — 모바일 우선, md(768px) 부터 사이드바
export const sidebar = style({ display: 'none', '@media': { [media.md]: { display: 'block', width: '15rem' } } });
export const menuButton = style({ '@media': { [media.md]: { display: 'none' } } });
export const tabbar = style({
  position: 'fixed', insetInline: 0, bottom: 0, paddingBottom: 'env(safe-area-inset-bottom, 0px)',
  background: vars.color.bg.default, borderTop: `1px solid ${vars.color.border.default}`, zIndex: 10, // 오버레이(vars.zIndex.overlay)보다 낮게
  '@media': { [media.md]: { display: 'none' } },
});
export const main = style({ paddingBottom: '5rem', '@media': { [media.md]: { paddingBottom: 0 } } });
```

## 시간 고르기 (예약·배송 시간)

시간 전용 컴포넌트(TimePicker)는 아직 없어요. 상황에 따라 이미 있는 컴포넌트로 충분해요 — 필요한 경우가 있으면
[Discussions](https://github.com/Dev-BestOW/BestOW-UI/discussions)로 알려 주세요.

- **정해진 시간 중 고르기(예약 슬롯·배송 시간대)** — 대부분의 예약 화면이 이 경우예요. 몇 개면 [RadioGroup](?path=/docs/components-radiogroup--docs)·[SegmentedControl](?path=/docs/components-segmentedcontrol--docs),
  많으면 [Select](?path=/docs/components-select--docs)·[NativeSelect](?path=/docs/components-nativeselect--docs). 마감된 시간은 `disabled` 로 두고 이유를 도움말에 써요.
- **아무 시각이나 입력(알림 시각·영업시간)** — [FormField](?path=/docs/components-formfield--docs) + 네이티브 `<input type="time">`. 모바일은 운영체제 시간 선택기가 뜨고,
  `min`·`max`·`step`(초 단위, 30분 = `1800`)을 줄 수 있어요. 값은 `'HH:mm'`(24시간) 문자열이라 날짜 값처럼 시간대 문제가 없어요.
  화면 표시(오전/오후)는 브라우저 언어를 따라요.

```tsx
// 정해진 시간대
<RadioGroup label="배송 시간" options={[
  { value: '09-12', label: '오전 9시 ~ 12시' },
  { value: '12-15', label: '오후 12시 ~ 3시', disabled: true, description: '마감됐어요' },
  { value: '15-18', label: '오후 3시 ~ 6시' },
]} value={slot} onValueChange={setSlot} />

// 아무 시각
<FormField label="알림 받을 시각" helperText="밤 9시 이후에는 보내지 않아요">
  {(field) => <Input type="time" min="07:00" max="21:00" step={1800} defaultValue="09:00" {...field} />}
</FormField>
```

## 목록 화면

검색·필터 → 표 → 행 선택과 일괄 작업 → 페이지 이동 → 행 메뉴로 상세(Drawer)·작업.
([Table — 목록 화면 패턴](?path=/story/components-table--list-pattern-story), 예제 앱 주문 관리)

- 검색 칸은 [SearchInput](?path=/docs/components-searchinput--docs)(지우기 버튼·Escape). 걸어 둔 조건은 [Tag](?path=/docs/components-tag--docs) + `TagGroup` 으로 보여 주고 하나씩 지우게 해요 —
  마지막 태그를 지워도 포커스가 갈 곳이 있게 `TagGroup` 은 늘 그려 둬요.

- 행 선택은 `useTableSelection` — "이 페이지 모두 선택"(일부면 혼합 상태)과 행 체크박스 prop 을 돌려주고, 페이지를 넘겨도 유지돼요.
  행 체크박스 이름은 "ORD-001 선택" 처럼 행을 구분할 수 있게.
- 선택하면 일괄 작업 바(Card + 버튼)를 보여 주고 "N건 선택됨" 을 `role="status"` 로 알려요.
- 결과가 없으면 `TableEmpty` 안에 [EmptyState](?path=/docs/components-emptystate--docs)(`size="sm" titleAs="p"`, 안내 + 초기화 버튼), 불러오는 동안은 `TableSkeleton` + 표에 `aria-busy`.
- 검색·필터로 결과 수가 바뀌면 "37건 중 1–10" 같은 문구를 `role="status"` 로 알려요(포커스는 그대로).
- 아이콘만 있는 열 머리글은 [VisuallyHidden](?path=/docs/components-visuallyhidden--docs)으로 이름("작업")을 준다.
- 행 메뉴(DropdownMenu)에서 연 Drawer·Modal 은 닫히면 메뉴 버튼으로 포커스가 돌아가요(자동).
- 상세의 이름–값은 [DescriptionList](?path=/docs/components-descriptionlist--docs).

```tsx
const selection = useTableSelection<string>();
<Checkbox aria-label="이 페이지 모두 선택" {...selection.selectAllProps(pageIds)} />;
{
  rows.length === 0 ? (
    <TableEmpty colSpan={8}>
      <EmptyState
        size="sm"
        titleAs="p"
        title="조건에 맞는 주문이 없어요."
        action={<Button onClick={reset}>초기화</Button>}
      />
    </TableEmpty>
  ) : (
    rows.map((row) => (
      <TableRow key={row.id} selected={selection.isSelected(row.id)}>
        <TableCell>
          <Checkbox aria-label={`${row.id} 선택`} {...selection.rowProps(row.id)} />
        </TableCell>
        …
      </TableRow>
    ))
  );
}
```

## 단계별 흐름 (가입·결제)

- 위에 [Stepper](?path=/docs/components-stepper--docs)로 현재 단계를 보여 주고, 이동은 "이전"·"다음" 버튼으로 해요(Stepper 는 표시용).
- 단계가 바뀌면 **새 단계의 제목으로 포커스**를 옮겨 바뀐 것을 알려요 — 제목에 `tabIndex={-1}`.
- 다음으로 가기 전에 그 단계의 칸을 검증하고, 실패하면 ErrorSummary.
- react-hook-form + zod 라면 **단계마다 폼(useForm)과 스키마를 따로** 둬요. 하나의 폼으로 묶으면 비밀번호 확인 같은 `.refine` 이 다른 단계 칸이 모두 채워질 때까지 확인되지 않아요.
  마지막 단계에서 모은 값을 서버 액션 하나로 보내고, 서버도 같은 스키마로 다시 확인해요. 완성된 예는 Next.js 템플릿 [`examples/next-starter`](https://github.com/Dev-BestOW/BestOW-UI/tree/main/examples/next-starter).

```tsx
const titleRef = useRef<HTMLHeadingElement>(null);
useEffect(() => { titleRef.current?.focus(); }, [step]);

<Stepper aria-label="회원가입 단계" steps={steps} current={step} />
<Typography ref={titleRef} variant="h2" tabIndex={-1}>{steps[step].label}</Typography>
…
<Button variant="outline" color="neutral" disabled={step === 0} onClick={() => setStep(step - 1)}>이전</Button>
<Button onClick={next}>다음</Button>
```

## 파일 업로드와 진행률

[FileUpload](?path=/docs/components-fileupload--docs)는 파일을 고르기만 해요. 서버로 보내는 동안 [Progress](?path=/docs/components-progress--docs)로
진행률을 보여 주고, 끝나면 Toast 나 `role="status"` 로 결과를 알려요. 형식·크기 검사는 편의용이라 **서버에서 다시 검사**해요.

```tsx
const [progress, setProgress] = useState<number | null>(null);

<FileUpload
  label="증빙 서류"
  accept=".pdf,image/*"
  maxSize={10 * 1024 * 1024}
  value={files}
  onValueChange={setFiles}
/>;
{
  progress !== null && <Progress label="업로드" value={progress} showValue />;
}
<Button loading={progress !== null && progress < 100} onClick={() => upload(files, setProgress)}>
  업로드
</Button>;
```

## 화면 안내·결과 알림

- 동작 결과(저장·삭제)는 Toast — 사라지므로 되돌리기처럼 중요한 동작을 Toast 에만 두지 않아요.
- 페이지에 남아야 하는 안내는 Alert(처음부터 있으면 역할 없음, 동작 뒤 새로 나타나면 `role="status"`/`"alert"`).
- 버튼을 누르고 기다리는 동안은 `Button loading` — 버튼 이름은 그대로 읽히고 중복 제출을 막아요.
